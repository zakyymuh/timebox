# Timebox v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android app that takes one written intention each morning and throws a full-screen wall over off-plan apps the moment they open, asking why — with a home-screen widget that sets the day's intention in one tap.

**Architecture:** Two Gradle modules. `:core` is a pure Kotlin JVM library holding every decision the app makes (block or allow, is this reason real, what should the widget show) — no `android.*` on its classpath, so the rules are tested in milliseconds by plain JUnit. `:app` is the Android shell: an `AccessibilityService` that reports foreground package names into `:core`, a Room database, Compose screens, and a Glance widget. The compiler enforces the boundary.

**Tech Stack:** Kotlin, Jetpack Compose + Material 3, navigation-compose, Room, Jetpack Glance, AccessibilityService, AlarmManager. JUnit 4 for `:core`, Robolectric for `:app`.

**Spec:** `docs/superpowers/specs/2026-10-26-timebox-design.md`

## Global Constraints

- Package root `dev.zakyymuh.timebox`; `:core` classes under `dev.zakyymuh.timebox.core`.
- `minSdk 29`, `compileSdk 36`, `targetSdk 36`, Java/Kotlin JVM target 17.
- **`:core` must not depend on Android.** Its `build.gradle.kts` applies `kotlin("jvm")` only. Anything needing a `Context` belongs in `:app`.
- **The manifest declares no `INTERNET` permission, in any task.** The gate is offline by design.
- Accessibility service config sets `android:canRetrieveWindowContent="false"` and subscribes only to `typeWindowStateChanged`. Timebox reads package names, never screen content.
- Dependency versions live in `gradle/libs.versions.toml` and resolve to the current stable release at implementation time. **Do not pin versions from memory** — run `./gradlew dependencies` or let Android Studio's catalog fill them, and confirm the build passes.
- Phone only. Every activity declares `android:screenOrientation="portrait"`, the gate included — a rotation mid-gate must not recreate the wall into a blank state.
- All time handling goes through an injected `java.time.Clock`. No `Instant.now()` / `LocalDate.now()` without a clock, anywhere.
- Gate defaults, exact values: reason needs **15** characters, **3** words of 2+ characters, **6** distinct characters; countdown **10** seconds; pass lasts **5** minutes.
- Each task ends with a commit.

## Review Focus

Five failure modes the spec implies. Each has a test in the task that owns the code.

1. **The wall relaunches in a loop.** One app launch fires several `typeWindowStateChanged` events, and the wall is itself a window. Without an own-package filter and same-package collapsing, the gate restarts over itself forever. → Task 5.
2. **A pass expires while I am still inside the app.** No new foreground event fires, so nothing re-gates me and the 5-minute pass becomes an hour. → Task 7.
3. **The accessibility service is off and the app says nothing.** Switched off in Settings, or killed and not restarted: the app looks installed and does nothing. → Task 8.
4. **No note exists yet.** Fresh install, or 2am before the morning note. `todaysPlan` is null; the gate must still block, name that reason, and offer to write one — not crash, not silently allow. → Task 1 (rule) and Task 6 (screen).
5. **The reason field is gamed.** `"aaaaaaaaaaaaaaaa"` and 15 spaces both clear a naive length check, and the gate becomes a formality. → Task 1.

Also pinned by tests, one level down: the widget flipping state at midnight (Task 10), and a pass granted before a reboot still being expired after it (Task 2).
